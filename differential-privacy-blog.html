Introduction — Differential Privacy in Data Warehouse & Mining

A Data Warehouse is a centralised repository that stores large volumes of structured data collected from multiple sources — sales systems, hospital records, banking transactions, user behaviour logs — all integrated for analytical querying and reporting.

Data Mining is the process of discovering hidden patterns, associations, and insights from this warehouse data using techniques such as classification, clustering, association rule mining, and regression.

But as organisations mine increasingly personal data — health records, financial histories, browsing patterns — a critical question arises: How do we extract meaningful insights without exposing individual records?

The Core Problem

Traditional data mining on a warehouse gives accurate results — but every query potentially leaks information about specific individuals. Published statistics, even aggregates, can be reverse-engineered to reveal private details. This is called a privacy attack.

Differential Privacy (DP), first formalised by Cynthia Dwork in 2006, provides a mathematical solution: add carefully calibrated noise to query outputs so that no individual's data can be reliably inferred — while still preserving the overall statistical accuracy of the result.

Why Privacy Matters in Data Mining

When data is mined from a warehouse without privacy protection, several classes of attacks become possible:

  • Re-identification Attack: A 2006 study showed that 87% of US citizens could be uniquely identified from just three fields — zip code, date of birth, and gender — all commonly stored in data warehouses.
  • Differencing Attack: Running two queries ("total salary of all employees" vs "total salary excluding Alice") reveals Alice's exact salary. A classic data warehouse vulnerability.
  • Linkage Attack: Joining an "anonymised" warehouse table with a public dataset to re-identify individuals.
Real Breach Example

The Netflix Prize dataset (2006) was released as "anonymised." Within weeks, researchers re-identified users by cross-referencing with public IMDb reviews — demonstrating that stripping names is not sufficient protection.

Differential Privacy directly addresses all three attack classes by providing a mathematical guarantee at the query output level — not just at the data storage level.

What is Differential Privacy? — Formal Definition

A randomised algorithm M satisfies ε-Differential Privacy if, for any two datasets D and D' that differ by exactly one record, and for any possible output S:

Pr[M(D) ∈ S] ≤ eε × Pr[M(D') ∈ S]

In plain English: the probability of any output changes by at most a factor of eε, whether or not any single individual's record is present. An observer cannot tell the difference between the two cases.

Simple Analogy — The Survey Coin Flip

Imagine a data warehouse analyst wants to know how many employees in a company have a salary above ₹1,00,000. Instead of directly querying the warehouse, each employee uses randomised response:

  • Flip a coin secretly.
  • Heads → Answer truthfully (Yes/No).
  • Tails → Always say "Yes."

The analyst receives noisy answers, but can statistically correct for the coin bias and estimate the true count — while no individual answer can be trusted as ground truth. This is the essence of local differential privacy.

Epsilon (ε) — The Privacy Parameter

Epsilon is the central control knob of every differentially private system. It directly governs the privacy-accuracy trade-off:

  • A smaller ε → more noise added → stronger privacy, less accurate results.
  • A larger ε → less noise added → weaker privacy, more accurate results.
  • ε = 0 → perfect privacy (output is completely random, useless).
  • ε → ∞ → no privacy (equivalent to publishing raw data).

How Noise is Added — The Laplace Mechanism

The most widely used noise mechanism in Differential Privacy for numerical queries in data warehouses is the Laplace Mechanism. Noise is drawn from a Laplace distribution scaled to the sensitivity of the query divided by epsilon.

Noise ~ Laplace(0, Δf / ε)

Δf = Global Sensitivity = max change in query result when one record changes
ε = Privacy parameter (chosen by system designer)
b = Laplace scale = Δf / ε
// Figure 4 — Laplace Distribution: Noise Probability Curve

The Laplace distribution is centred at zero, meaning most of the time the noise added is small. Large noise values are possible but increasingly unlikely. This is what keeps results useful while still providing the privacy guarantee.

Worked Numerical Examples

These step-by-step examples show exactly how Differential Privacy is applied to real data warehouse queries. These are the type of problems asked in university exams.

Example 1 Laplace Mechanism — Average Salary Query

Problem: A data warehouse stores employee salary records. An analyst wants to publish the average salary of all employees. Apply the Laplace mechanism with ε = 0.5. Assume salary range is ₹20,000 to ₹1,20,000.

1
Identify the True Query Result:
Suppose the true average salary of 100 employees = ₹65,000
2
Calculate Global Sensitivity (Δf):
Sensitivity = maximum change one employee can cause in the average.
When one record changes from ₹20,000 to ₹1,20,000 in a group of 100:
Δf = (₹1,20,000 − ₹20,000) / 100 = ₹1,000
Δf = (Max Salary − Min Salary) / n
Δf = (1,20,000 − 20,000) / 100
Δf = ₹1,000
3
Calculate Laplace Scale (b):
b = Δf / ε = 1,000 / 0.5 = 2,000
b = Δf / ε = 1,000 / 0.5
b = 2,000
4
Sample Noise from Laplace(0, 2000):
Suppose the random noise drawn = +₹874 (this is random each time)
5
Add Noise to True Answer:
Published Result = True Answer + Noise = 65,000 + 874 = ₹65,874
Published Average = True Average + Laplace Noise
= ₹65,000 + ₹874
= ₹65,874 (This is what is released publicly)
✅ Result: ₹65,874 published | Individual salaries: PROTECTED | Utility: HIGH (error < 1.5%)
Example 2 COUNT Query — Number of Patients with Diabetes

Problem: A hospital data warehouse is queried: "How many patients have been diagnosed with diabetes?" True count = 340 patients (out of 1,000). Apply DP with ε = 1.0.

1
True Query Result: Count = 340 patients
2
Global Sensitivity for COUNT query:
For a COUNT query, adding or removing one record changes the count by exactly 1.
Therefore: Δf = 1
3
Laplace Scale:
b = Δf / ε = 1 / 1.0 = 1
b = 1 / 1.0 = 1
4
Noise Sampled from Laplace(0, 1):
Suppose noise = +2.3 → rounded to nearest integer = +2
5
Published Result:
= 340 + 2 = 342
Published Count = True Count + Noise
= 340 + 2
= 342 patients
✅ Result: 342 published | Each patient's record: PROTECTED | Error: 0.6% — Excellent accuracy
Example 3 Differencing Attack — and How DP Stops It

Problem: A data warehouse has 5 employees. An attacker runs two queries to find Alice's salary.

1
Without DP (Vulnerable):
Q1: SUM of salaries of all 5 employees = ₹4,50,000
Q2: SUM of salaries of 4 employees (excluding Alice) = ₹3,60,000
Alice's salary = 4,50,000 − 3,60,000 = ₹90,000 ← LEAKED!
2
With DP (ε = 0.5, Δf = max salary / 1 = ₹1,20,000, b = 2,40,000):
Q1 (true) = ₹4,50,000 → Add noise (+₹18,500) → Published: ₹4,68,500
Q2 (true) = ₹3,60,000 → Add noise (−₹21,200) → Published: ₹3,38,800

Attacker computes: 4,68,500 − 3,38,800 = ₹1,29,700
True Alice salary = ₹90,000 ← Attacker is off by ₹39,700. ATTACK FAILS ✅
✅ Differencing attack defeated. Alice's real salary (₹90,000) cannot be recovered from the noisy outputs.

Synthetic Data Generation with Differential Privacy

One of the most powerful applications of DP in Data Warehouse & Mining is synthetic data generation. Instead of sharing the real warehouse data with analysts, a differentially private synthesizer generates a fake dataset that has the same statistical properties — but contains no real records.

📊 Figure 5 — DP Synthetic Data Pipeline: Original data → DP Synthesizer (noise added during training) → Synthetic data → Analysis. No real individual's data leaves the warehouse.

The process shown in the diagram works as follows:

  1. Original Data — Real warehouse records (e.g., patient records, salary data). A human icon indicates individual identities are attached.
  2. DP Synthesizer — A machine learning model (e.g., GAN, Bayesian network) is trained on the real data, but noise is added during training using DP-SGD (Differentially Private Stochastic Gradient Descent). The noise icon (orange waveform) represents this process.
  3. Synthetic Data — A new dataset is generated. The records look realistic and preserve statistical distributions — but correspond to no real person. The muted human icon indicates real identities are removed.
  4. Analysis & Mining — Analysts can now run classification, clustering, or association rule mining on this synthetic data without any privacy risk.
Why This Matters for Data Warehouses

Many organisations cannot share their warehouse data with external data scientists due to regulatory reasons (GDPR, HIPAA). DP synthetic data solves this — the synthetic copy can be shared freely, because it provides no information about specific individuals, by mathematical guarantee.

Differential Privacy in Association Rule Mining

Association rule mining (e.g., Apriori algorithm) is a core technique in Data Mining used to find frequent itemsets — for example, "customers who buy bread also buy butter." When applied to a data warehouse containing personal transactions, DP is applied to the support counts.

Advantages and Disadvantages

✅ Advantages

  • Mathematical, provable privacy guarantee
  • Works against adversaries with background knowledge
  • Enables safe data warehouse sharing and publication
  • Composable — total privacy cost is trackable
  • Complies with GDPR, HIPAA, DPDP Act
  • Supports both local and central DP deployment models

❌ Disadvantages

  • Noise reduces accuracy, especially for small datasets
  • Choosing the right ε requires expertise
  • Complex implementation — subtle errors break the guarantee
  • Local DP requires much more noise than central DP for same accuracy
  • Difficult to explain to non-technical management
  • Privacy budget degrades with each additional query

Viva Questions & Model Answers

Define Differential Privacy. How does it differ from traditional anonymisation?

Differential Privacy is a mathematical framework that guarantees the output of any computation changes by at most a factor of eε when any single individual's record is added to or removed from the dataset. This provides a formal, quantifiable, and provable privacy guarantee.

Traditional anonymisation merely removes identifiers (names, IDs) from data — a technique that has been repeatedly broken through re-identification attacks. DP is superior because it is robust even when the adversary has arbitrary background knowledge, and the guarantee is mathematical rather than heuristic.

What is the Laplace mechanism and how is the noise scale calculated?

The Laplace mechanism adds noise drawn from a Laplace distribution to the true query result. The scale of this distribution is b = Δf / ε, where Δf is the global sensitivity (maximum change in the query result when one record changes) and ε is the privacy parameter.

For a COUNT query, Δf = 1. For a SUM or AVERAGE query, Δf depends on the range of values. A smaller ε means larger b, which means more noise and stronger privacy.

What is a differencing attack on a data warehouse, and how does DP prevent it?

A differencing attack occurs when an attacker runs two queries — one including a target individual and one excluding them — and subtracts the results to infer the individual's private value. For example: "Total salary of all employees" minus "Total salary excluding Alice" reveals Alice's exact salary.

Differential Privacy prevents this by adding independent noise to each query output. Since the noise is random and unpredictable, the subtraction yields a result that is far from the true individual value, making the attack ineffective. The mathematical guarantee ensures the attacker learns at most ε bits of information about any individual.

What is the privacy-accuracy trade-off in Differential Privacy? Give an example.

The privacy-accuracy trade-off is the fundamental tension in DP: stronger privacy (smaller ε) requires adding more noise, which reduces the accuracy of query results. Weaker privacy (larger ε) adds less noise, giving more accurate results but weaker individual protection.

Example: For a COUNT query with Δf=1, using ε=0.1 gives b=10 (large noise, ±10–20 typically). Using ε=10 gives b=0.1 (tiny noise, ±0.1–0.5 typically). For a hospital with 340 diabetes patients, ε=0.1 might publish "328" or "355" — still useful but imprecise. ε=10 would publish "340" or "341" — very accurate, but each individual patient is less protected.

Conclusion

Differential Privacy represents the most rigorous answer yet to one of data science's oldest and hardest problems: how do we learn from data without exposing the individuals who generated it?

In the context of Data Warehousing & Mining, DP applies at every stage — from aggregate queries and association rule mining to synthetic data generation and classification model training. It transforms privacy from a vague policy commitment into a mathematical property of the system itself.

The key ideas to remember: the Laplace mechanism adds calibrated noise scaled to sensitivity and epsilon; epsilon is the privacy budget controlling the trade-off; and the fundamental guarantee is that no observer can reliably determine any individual's contribution from the published output.

Key Takeaways

DP gives us mathematics-backed protection — not just promises — while preserving the analytical power of data warehouse mining.
